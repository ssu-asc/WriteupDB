# cachebrowns

## 문제 설명

> I hate technology, can't even enjoy a delicious golden breakfast at the cafeteria without having to connect to the internet. Guess I'll have to go to work hungry, people need to spend more time making sure these stupid software actually works.

## 풀이

### 분석

문제에서 제공한 main.java를 확인해봤다.

`main()`의 핵심 로직은 다음과 같다.

```java
String input = s.nextLine();
if (input.length() < 16) {
    out.println("Passwords must be at least 16 characters long.");
    System.exit(1);
}

if (auth(input.hashCode())) {
    out.println("Authenticated! Here are your hash browns: 🥔🥔🥔");
    displayFlag();
} else {
    out.println("Wrong password.");
    System.exit(1);
}
```

따라서 입력은 다음 두 조건을 만족해야 한다.

1. 문자열 길이가 16 이상이어야 한다.
2. `input.hashCode()`를 `auth()`에 전달했을 때 `true`가 반환되어야 한다.

허용된 해시코드 목록과 인증 함수는 다음과 같다.

```java
static Integer[] PERMITTED_HASHCODES = new Integer[] {
    982114681, -1367319387, 1329033977, 904090737,
    -862545276, -762593117, -110, 81925023,
    5810259, -2959105, 1029, 96320135, -29692049, 128
};

static boolean auth(Integer inputHash) {
    for (Integer permittedHashcode : PERMITTED_HASHCODES) {
        if (permittedHashcode == inputHash) {
            return true;
        }
    }
    return false;
}
```

여기서 목록과 매개변수의 타입은 기본형 `int`가 아니라 래퍼 클래스 `Integer`이다.

### 취약점

Java에서 객체에 대한 `==` 연산은 값이 아닌 동일한 객체를 참조하는지를 비교한다. 정상적인 값 비교라면 다음과 같이 `equals()`를 사용해야 한다.

```java
if (permittedHashcode.equals(inputHash)) {
    return true;
}
```

하지만 Java는 일반적으로 `-128`부터 `127`까지의 `Integer` 객체를 캐싱한다. 이 범위의 `int`가 오토박싱되면 `Integer.valueOf()`가 동일한 캐시 객체를 반환한다.

```java
Integer a = -110;
Integer b = -110;
System.out.println(a == b); // true
```

`PERMITTED_HASHCODES` 중 기본 캐시 범위에 포함되는 값은 `-110`이다. 다음 두 값은 모두 `Integer.valueOf(-110)`으로 박싱되어 동일한 캐시 객체를 참조한다.

- 배열에 저장된 `Integer(-110)`
- `auth(input.hashCode())` 호출 과정에서 박싱된 `Integer(-110)`

따라서 길이가 16 이상이고 `String.hashCode()`가 `-110`인 문자열을 입력하면 `==` 비교가 참이 된다. 목록의 `128`은 기본 Integer 캐시 범위를 벗어나므로 `-110`을 사용하는 것이 확실하다.

Java의 `String.hashCode()`는 각 UTF-16 코드 단위에 대해 다음 점화식으로 계산되며, 정수 오버플로는 $2^{32}$ 모듈러 연산과 같다.

```text
h₀ = 0
hᵢ₊₁ = 31 × hᵢ + charᵢ  (mod 2³²)
```

해시 함수는 암호학적 해시가 아니므로 원하는 32비트 결과를 갖는 문자열을 찾을 수 있다.

### 익스플로잇

길이 조건을 맞추기 위해 10자의 고정 접두사 `AAAAAAAAAA`를 사용하고, 뒤의 영숫자 6자를 탐색했다. 6자 전체를 순차 대입하는 대신 3자씩 좌우로 나누는 meet-in-the-middle 방식을 사용한다.

최종 문자열을 `prefix || left || right`라고 하면 다음 관계가 성립한다.

```text
final_hash = prefix_hash × 31⁶ + hash(left) × 31³ + hash(right)  (mod 2³²)
```

먼저 가능한 3자 `right`의 해시를 테이블에 저장한다. 이후 각 `left`에 대해 최종 해시가 `-110`이 되기 위해 필요한 `right` 해시를 계산하여 테이블에서 찾는다.

```python
import itertools
import socket
import string

HOST = "34.40.133.67"
PORT = 7777
MOD = 1 << 32
TARGET = (-110) % MOD
CHARS = string.ascii_letters + string.digits
PREFIX = "A" * 10


def java_hash(text: str) -> int:
    """Java String.hashCode()의 부호 없는 32비트 표현을 반환한다."""
    value = 0
    for ch in text:
        value = (31 * value + ord(ch)) % MOD
    return value


def find_password() -> str:
    prefix_hash = java_hash(PREFIX)
    power3 = 31 ** 3

    right_by_hash = {}
    for chars in itertools.product(CHARS, repeat=3):
        right = "".join(chars)
        right_by_hash.setdefault(java_hash(right), right)

    for chars in itertools.product(CHARS, repeat=3):
        left = "".join(chars)
        required_right = (
            TARGET
            - prefix_hash * power3 * power3
            - java_hash(left) * power3
        ) % MOD

        if required_right in right_by_hash:
            password = PREFIX + left + right_by_hash[required_right]
            assert len(password) >= 16
            assert java_hash(password) == TARGET
            return password

    raise RuntimeError("조건에 맞는 문자열을 찾지 못했습니다.")


password = find_password()
signed_hash = java_hash(password)
if signed_hash >= (1 << 31):
    signed_hash -= MOD

print(f"password = {password}")
print(f"length   = {len(password)}")
print(f"hashCode = {signed_hash}")

with socket.create_connection((HOST, PORT)) as sock:
    print(sock.recv(4096).decode(), end="")
    sock.sendall(password.encode() + b"\n")

    response = bytearray()
    while True:
        chunk = sock.recv(4096)
        if not chunk:
            break
        response.extend(chunk)

    print(response.decode(), end="")
```

탐색 결과 다음 문자열을 얻었다.

```text
password = AAAAAAAAAAoqsfda
length   = 16
hashCode = -110
```

이를 서버에 입력하면 인증에 성공한다.

## 배운 점

- Java 래퍼 클래스의 `==`는 값이 아니라 객체 참조를 비교하므로, 값 비교에는 `equals()`를 사용해야 한다.
- 작은 정수에 대한 `Integer` 캐싱 때문에 잘못된 참조 비교가 일부 값에서만 참이 되는 예상하기 어려운 동작이 발생할 수 있다.
- `String.hashCode()`는 빠른 해시 테이블 연산을 위한 비암호학적 함수이므로 인증이나 무결성 검증에 사용하면 안 된다.
- 6자 전수조사처럼 탐색 공간이 큰 문제도 식을 둘로 분리할 수 있다면 meet-in-the-middle로 효율적으로 줄일 수 있다.
