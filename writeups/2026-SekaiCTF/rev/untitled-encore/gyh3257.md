# Untitled Encore

## 문제 설명

> A rhythm game chart validator with an embedded eBPF ELF. Submit a valid 40-byte chart via `--check-chart <hex>` to get the flag.

## 풀이

### 분석

**바이너리 구조**

- Windows PE64 (`untitled-encore.exe`)
- CLI 모드: `--check-chart <40-byte-hex>` / `--print-template`
- `.rdata` 섹션 오프셋 `0xcf00`에 eBPF ELF 내장 (VA `0x14000e700`)

**핵심 함수 흐름 (`FUN_140009d30` — `--check-chart` 핸들러)**

```
chart (40 bytes = 20 notes × 2 bytes)
  │
  ├─► FUN_1400031f0  → 차트 해시 검증 + lane/kind acc 계산
  │     요구: hash[0]=0xd75245e2, hash[1]=0x3bbe10e9
  │            hash[2]=0x3c500f48, hash[3]=0x01ebd885
  │            lane_acc=[0x38,0x22,0x36,0x21,0x41]
  │            kind_acc=[0x61,0x49,0x3c]
  │
  ├─► FUN_140006bf0  → eBPF ELF 파싱 → .text / .rodata 추출
  │
  ├─► FUN_140005ab0  → eBPF .rodata 인터프리터 (커스텀 VM)
  │     output[0..31] = Branch C 결과
  │     output[32..63] = Branch D 결과
  │
  ├─► FUN_140006810  → (chart + output[0..31])로 중간 해시 계산
  │
  ├─► FUN_1400085c0  → eBPF .text 실행 (또 다른 커스텀 VM)
  │     결과 ≡ output[32..63] 이어야 함 (memcmp 검증)
  │
  └─► FUN_140003a10  → 플래그 XOR 출력
        flag = template42[20:42] XOR key[0:22]
```

### 풀이 과정

#### Step 1: eBPF .rodata 디코딩

`.rodata`에는 커스텀 포맷의 인스트럭션 스트림이 있다.

```
signature(14 bytes) | type(1) | offset(1) | size(2LE) | skip(N) | instructions
```

`offset=0x16`, `size=0x184=388` → 인스트럭션 스트림은 `rodata[40:]` (388 bytes = 97 그룹).

각 그룹 4바이트를 XOR 복호화:
```python
cVar4 = ctypes.c_int8(byte_offset).value  # byte_offset = group_idx * 4
d0 = raw[0] ^ ((cVar4 * 0x11 + 0xa3) & 0xff)
d1 = raw[1] ^ ((cVar4 * 0x1d + 0x11) & 0xff)
d2 = raw[2] ^ ((cVar4 * 0x1f + 0x7b) & 0xff)
d3 = raw[3] ^ ((cVar4 * 0x25 - 0x3b) & 0xff)
```

복호화 결과:
- Groups 0-11: **Branch A** (0x21) — pvVar7 고정값 검증 (항상 통과)
- Groups 12-31: **Branch B** (0x44) — 20개 note 검증, 순서: `[16,9,18,19,2,15,6,8,17,11,4,0,3,5,14,7,10,13,12,1]`
- Groups 32-63: **Branch C** (0x62) — output[0..31] 계산
- Groups 64-95: **Branch D** (0x8b) — output[32..63] 계산
- Group 96: **EXIT** (0xf0)

#### Step 2: Branch B 역산 (차트 복원)

각 Branch B 그룹의 제약:
```python
val = (timing * 0x1f + byte1 * 0x11 + uVar14 + note_idx * 0x49) & 0xffff
bVar10 = (val >> 8) ^ (val & 0xff)       # must == d2
new_h = rotl32((uVar14 ^ val) + ((byte1<<8)|timing) + bVar10, (note_idx&7)+1)
# (new_h & 0xff) must == d3
```

**백트래킹 DFS**로 모든 20개 note에 대해 유효한 `(byte1, timing)` 쌍을 순차 탐색:

```python
def solve(step, uVar14, chart):
    if step == 20: return chart
    n, d2_exp, d3_exp = branch_b_order[step]
    for bVar1 in range(3, 17):
        for lane in range(5):
            for kind in range(3):
                bVar15 = (lane - n) & 1
                for bVar16 in range(2):
                    bVar2 = lane|(kind<<3)|(bVar16<<5)|(bVar15<<6)
                    # ... 제약 확인 ...
                    result = solve(step+1, new_h, chart)
                    if result: return result
    return None
```

**획득한 차트 (40 bytes hex):**
```

```

## 배운 점

- **커스텀 eBPF-like VM**: 표준 eBPF가 아닌 커스텀 32바이트 인스트럭션 포맷. `.rodata` 인스트럭션 스트림이 차트 검증 로직을 담고 있음
- **XOR 암호화 인스트럭션**: 그룹 인덱스 기반 키(부호 있는 바이트 오프셋)로 XOR 복호화해야 실제 브랜치 코드가 보임
- **역추적 제약 충족**: 순차적 해시 상태 의존성 때문에 나이브한 그리디가 실패하고, DFS 백트래킹이 필요
- **WSL2에서 Windows 바이너리 실행**: `/mnt/c/` 경로를 통해 Windows 실행 파일을 직접 실행 가능
