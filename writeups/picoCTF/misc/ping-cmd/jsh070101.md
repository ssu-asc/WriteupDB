# 문제명

## 문제 설명

Can you make the server reveal its secrets? It seems to be able to ping Google DNS, but what happens if you get a little creative with your input?

## 풀이

### 분석

 첫 번째 힌트에서는 프로그램이 내부적으로 셸 명령어를 사용한다는 내용을 알려주었고, 두 번째 힌트에서는 한 번에 여러 개의 명령어를 실행할 수도 있다는 내용을 알려주었다.

처음에는 '셸 명령어'라는 말 자체가 익숙하지 않아 찾아보았다. 셸 명령어는 리눅스 터미널에서 사용하는 ls, cat, ping 같은 명령어를 의미한다는 것을 알게 되었다. 예를 들어 다음과 같이 입력하면 특정 IP 주소에 ping을 보낼 수 있다.

ping -c 1 8.8.8.8

또한 리눅스 셸에서는 세미콜론(;)을 이용하면 한 줄에서 여러 명령어를 순서대로 실행할 수 있다는 것도 알게 되었다.

echo hello; ls

위와 같이 입력하면 먼저 echo hello가 실행되고, 그다음 ls가 실행된다.

이 내용을 문제의 힌트와 연결해서 생각해보았다. 서버가 사용자가 입력한 IP 주소를 받아서 내부적으로 다음과 비슷하게 처리하고 있을 가능성이 있다고 생각했다.

os.system("ping -c 1 " + user_input)

만약 이런 구조라면 사용자가 단순한 IP 주소가 아니라 8.8.8.8; ls처럼 입력했을 때 실제로 서버에서는 다음과 같은 명령어가 만들어질 수 있다.

ping -c 1 8.8.8.8; ls

즉, 원래 서버가 실행하려던 ping뿐만 아니라 내가 추가한 ls 명령어까지 실행할 수 있을 것이라고 생각했다.

취약점

이 문제에서 사용된 취약점은 Command Injection(명령어 삽입) 이다.

Command Injection은 사용자가 입력한 값을 프로그램이 제대로 검사하지 않고 셸 명령어의 일부로 사용했을 때 발생할 수 있는 취약점이다. 공격자가 입력값 안에 ;, &&, | 등의 셸 특수문자를 넣으면 개발자가 원래 실행하려고 했던 명령어 이외의 다른 명령어까지 실행할 수 있다.

예를 들어 서버가 다음과 같은 방식으로 사용자의 입력값을 처리한다고 가정할 수 있다.

os.system("ping -c 1 " + user_input)

정상적으로 8.8.8.8을 입력하면 다음과 같이 실행된다.

ping -c 1 8.8.8.8

하지만 다음과 같이 입력한다면,

8.8.8.8; ls

최종적으로 서버에서는 다음과 같이 두 개의 명령어가 실행될 수 있다.

ping -c 1 8.8.8.8; ls

따라서 사용자가 IP 주소만 입력할 것이라고 믿고 입력값을 그대로 셸 명령어에 넣은 것이 이 문제의 핵심 취약점이라고 이해했다.

익스플로잇

먼저 문제에서 제공한 명령어를 이용하여 서버에 접속하였다.

nc mysterious-sea.picoctf.net 50262

여기서 nc도 처음 보는 명령어라서 찾아보았다. nc는 Netcat이라는 프로그램으로, 특정 서버의 IP 주소와 포트에 연결하여 데이터를 주고받을 수 있는 도구라는 것을 알게 되었다. CTF에서는 서버에 직접 접속해서 값을 입력해야 하는 문제에서 자주 사용된다고 한다.

서버에 접속한 뒤 우선 정상적인 기능부터 확인하기 위해 구글 DNS 주소인 8.8.8.8을 입력하였다.

8.8.8.8

그러자 정상적으로 ping 결과가 출력되었다. 이를 통해 내가 입력한 IP 주소를 이용하여 서버가 실제로 ping 명령어를 실행하고 있다는 것을 확인할 수 있었다.

여기서 flag.txt라는 이름의 파일이 있었기 때문에 플래그가 이 파일 안에 들어 있을 가능성이 높다고 생각했다.

리눅스에서 파일의 내용을 출력하는 명령어를 찾아보니 cat을 사용할 수 있다는 것을 알게 되었다. 따라서 앞에서 사용했던 것과 같은 방법으로 다음 값을 입력하였다.

8.8.8.8; cat flag.txt

이 입력값은 서버에서 결과적으로 다음과 비슷한 명령어로 실행되었을 것이라고 생각할 수 있다.

ping -c 1 8.8.8.8; cat flag.txt

실행 결과 ping 결과 뒤에 flag.txt의 내용이 출력되었고, 최종적으로 플래그를 확인할 수 있었다.

## 배운 점

이번 문제를 풀면서 처음으로 Command Injection이라는 취약점을 직접 사용해볼 수 있었다. 처음에는 단순히 IP 주소를 입력해서 ping을 보내는 서비스가 어떻게 보안 문제로 이어지는지 이해하기 어려웠지만, 힌트를 보고 셸 명령어와 세미콜론(;)의 역할을 하나씩 찾아보면서 이해할 수 있었다.

특히 리눅스에서 ;를 사용하면 여러 명령어를 순서대로 실행할 수 있고, ls는 현재 위치의 파일 목록을 확인하며, cat은 파일 내용을 출력하는 명령어라는 것을 배웠다. 또한 nc가 서버의 특정 포트에 연결할 때 사용할 수 있는 Netcat이라는 도구라는 것도 알게 되었다.

가장 중요하게 배운 점은 사용자가 입력한 값을 절대로 그대로 셸 명령어에 넣으면 안 된다는 것이다. 예를 들어 파이썬에서 사용자의 입력을 문자열로 이어 붙여 os.system()으로 실행하거나 subprocess.run()에서 shell=True를 사용하는 방식은 입력값에 따라 의도하지 않은 명령어가 실행될 위험이 있다.

따라서 실제 프로그램에서는 가능하면 셸을 거치지 않고 다음과 같이 명령어와 인자를 분리해서 실행하는 것이 더 안전하다는 것을 알게 되었다.

subprocess.run(["ping", "-c", "1", ip_address], shell=False)
