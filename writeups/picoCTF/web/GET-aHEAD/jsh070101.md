# 문제명

## 문제 설명

Find the flag being held on this server to get ahead of the competition

http://wily-courier.picoctf.net:54771/

## 풀이

### 분석

문제 이름이 GET aHEAD인 것을 보고 찾아보니 GET과 HEAD는 모두 HTTP 요청 방식이라는 것을 알게 되었다.

HTTP는 브라우저와 서버가 서로 데이터를 주고받을 때 사용하는 통신 규칙이다. 브라우저에서 웹사이트에 접속하면 서버에게 요청을 보내고, 서버는 그 요청에 대한 응답을 보내준다.

HTTP 요청에는 여러 가지 방식이 있는데 대표적으로 다음과 같다.

GET : 웹페이지나 파일을 가져올 때 사용하는 가장 일반적인 요청
POST : 로그인이나 회원가입처럼 서버에 데이터를 보낼 때 사용하는 요청
HEAD : GET과 비슷하지만 실제 페이지 내용은 받지 않고 응답의 정보만 받는 요청

문제 제목에 GET과 HEAD가 모두 들어있는 것을 보고 "GET 대신 HEAD 요청을 보내라는 의미가 아닐까?"라는 생각이 들었다.

문제에서 제공된 힌트도 확인해 보았다.

Maybe you have more than 2 choices

이 힌트는 GET과 POST만 있는 것이 아니라 HEAD와 같은 다른 HTTP Method도 있다는 것을 의미하는 것 같았다.

또 다른 힌트는

Check out tools like Burpsuite to modify your requests and look at the responses

였는데, Burp Suite를 이용하여 요청을 수정하고 응답을 확인해 보라는 의미였다.

Burp Suite는 미숙해서 사용법부터 알아보았다.


### 취약점

이 문제는 일반적인 보안 취약점을 공격하는 문제라기보다는 HTTP 요청 방식을 이해하고 올바른 요청을 보내는 문제이다.

웹 브라우저는 기본적으로 GET 요청을 보내지만, 서버는 HEAD 요청이 들어왔을 때 응답 헤더에 플래그를 포함하도록 설정되어 있었다.

즉, 사용자가 GET 요청만 사용하면 플래그를 볼 수 없고, HTTP Method를 HEAD로 변경해야만 플래그를 확인할 수 있다.

이 문제를 통해 서버는 요청 방식에 따라 서로 다른 응답을 보낼 수 있다는 점을 배울 수 있었다.



### 익스플로잇

먼저 Burp Suite Community Edition을 설치하였다.

Burp Suite는 브라우저와 서버 사이에서 오가는 HTTP 요청과 응답을 확인하거나 수정할 수 있는 웹 보안 도구이다.

이후 Proxy 메뉴에서 Burp Browser를 실행하였다.

Burp Browser에서 picoCTF 문제 사이트를 열고 Intercept를 활성화한 뒤 새로고침을 하였다.

그러자 브라우저가 서버로 보내는 HTTP 요청이 Burp Suite에서 가로채졌다.

처음에는 다음과 같은 요청이 보였다.

GET / HTTP/1.1
Host: mercury.picoctf.net

여기서 문제 제목을 떠올리며 첫 번째 줄의 GET을 HEAD로 수정하였다.

HEAD / HTTP/1.1
Host: mercury.picoctf.net

수정한 뒤 Send to Repeater 기능을 이용하여 Repeater로 요청을 보냈다.

Repeater는 같은 요청을 여러 번 수정하면서 다시 보내볼 수 있는 Burp Suite의 기능이다.

Repeater에서 HEAD 요청을 보낸 후 서버의 응답을 확인하였다.

응답의 Header 부분을 확인하니 플래그가 포함되어 있었고 이를 통해 문제를 해결할 수 있었다.

## 배운 점

이번 문제를 풀면서 HTTP Method에 대해 공부하게 되었다.

처음에는 웹사이트에 접속하면 모두 같은 요청을 보내는 줄 알았지만, GET, POST, HEAD처럼 여러 종류의 요청이 있다는 것을 알게 되었다.

또한 서버는 사용자가 어떤 HTTP Method를 사용하느냐에 따라 서로 다른 응답을 보낼 수 있다는 것도 배웠다.

이번 문제를 통해 HTTP 요청, HTTP 응답, Header, Method, Burp Suite 사용법 등 웹 해킹의 가장 기초적인 개념을 익힐 수 있었고, 단순히 웹페이지를 보는 것이 아니라 브라우저와 서버가 어떻게 통신하는지를 확인하는 방법을 배우게 되었다.
