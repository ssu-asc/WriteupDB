# 문제명

## 문제 설명

> 비밀번호를 입력받아 검증하는 간단한 "보안 로그인 포탈"이 주어진다. 접속 후 확인해보면 로그인 폼과 함께 JavaScript로 작성된 검증 로직이 페이지 소스에 그대로 노출되어 있다.

- http://fickle-tempest.picoctf.net:55444/

## 풀이

### 분석

1. 페이지 소스 확인

Ctrl+U (페이지 소스 보기)로 HTML을 열람하면 다음과 같은 JavaScript 코드를 확인할 수 있다.

javascript
function verify() {
  checkpass = document.getElementById("pass").value;
  split = 4;
  if (checkpass.substring(0, split) == 'pico') {
    if (checkpass.substring(split*6, split*7) == 'eb02') {
      if (checkpass.substring(split, split*2) == 'CTF{') {
        if (checkpass.substring(split*4, split*5) == 'ts_p') {
          if (checkpass.substring(split*3, split*4) == 'lien') {
            if (checkpass.substring(split*5, split*6) == 'lz_2') {
              if (checkpass.substring(split*2, split*3) == 'no_c') {
                if (checkpass.substring(split*7, split*8) == 'b45}') {
                  alert("Password Verified")
                }
              }
            }
          }
        }
      }
    }
  }
}


### 취약점

비밀번호 검증이 서버가 아닌 클라이언트(브라우저) JavaScript 내부에서 이루어지고 있다. 즉, 정답 문자열의 각 조각이 소스코드 안에 그대로 하드코딩되어 있어, 별도의 브루트포스나 서버 요청 없이 소스코드만 읽으면 정답을 알아낼 수 있다.

### 익스플로잇

split = 4이므로 비밀번호는 4글자씩 총 8조각(substring(split*n, split*(n+1)))으로 나뉘어 검증된다. 각 조건문에서 사용된 인덱스(n)를 기준으로 순서를 정리하면 다음과 같다.

인덱스 (n)	값
0	pico
1	CTF{
2	no_c
3	lien
4	ts_p
5	lz_2
6	eb02
7	b45}

인덱스 순서대로 이어 붙이면:

pico + CTF{ + no_c + lien + ts_p + lz_2 + eb02 + b45}

## 배운 점

민감한 검증 로직(비밀번호 확인, 인증 등)을 클라이언트 측 코드에 두면 안 된다.
브라우저에 전달되는 모든 코드와 데이터는 사용자가 100% 열람,조작 가능하다고 가정해야 한다.
반드시 서버 측에서 검증을 수행하고, 클라이언트는 UI/UX 목적으로만 사용해야 한다.
