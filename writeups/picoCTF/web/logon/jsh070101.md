# 문제명

## 문제 설명

> The factory is hiding things from all of its users.
Can you login as Joe and find what they've been looking at?

- 문제 URL / 파일 등 접속 정보

## 풀이

### 분석

처음에는 문제에서 요구하는 대로 Joe라는 사용자 이름으로 로그인해 보았다. 하지만 비밀번호를 정확하게 알 수 없었기 때문에 로그인에 실패했고, I'm sorry Joe's password is super secure. You're not getting in that way.라는 메시지가 출력되었다. 문제의 힌트에서 Joe의 비밀번호는 확인하는 것 같다고 했기 때문에, Joe의 비밀번호를 무작정 맞히는 방법보다는 로그인 과정 자체에 문제가 있는지 확인해 보기로 했다. 그래서 Joe가 아닌 다른 이름을 입력하고 비밀번호에는 아무 값이나 입력해 보았다. 그 결과 비밀번호를 정확하게 입력하지 않았는데도 Success: You logged in!이라는 메시지가 출력되었다. 이를 통해 Joe가 아닌 사용자는 비밀번호를 제대로 확인하지 않는다는 것을 알 수 있었다. 로그인에 성공한 후 /flag 페이지로 이동했지만 No flag for you라는 문구가 나타났다. 여기서 단순히 로그인에 성공하는 것과 관리자 권한을 가지고 Flag를 보는 것은 별개의 문제라는 것을 알게 되었다. 그래서 브라우저에서 F12를 눌러 개발자 도구를 열고 웹사이트에서 사용하는 정보를 확인하였다.

### 취약점

개발자 도구에서 Application, Cookies 메뉴로 들어가 현재 웹사이트의 쿠키를 확인하였다. 쿠키에는 다음과 같은 값들이 저장되어 있었다.

admin      False
password   ' OR 1=1 --
username   joe

여기서 admin이라는 쿠키가 눈에 띄었다. 일반적으로 관리자인지 여부와 같은 중요한 권한 정보는 서버에서 안전하게 확인해야 하는데, 이 문제에서는 브라우저에 저장된 admin 쿠키의 값을 이용하여 사용자의 관리자 여부를 판단하고 있었다. 쿠키는 사용자의 브라우저에 저장되는 값이기 때문에 개발자 도구를 이용하면 값을 직접 수정할 수 있다. 따라서 admin=False를 admin=True로 변경하면 서버가 사용자를 관리자로 인식할 가능성이 있다고 판단하였다. 이처럼 사용자가 직접 변경할 수 있는 쿠키 값을 신뢰하여 권한을 결정하는 것이 이 문제의 핵심 취약점이다. 또한 처음 로그인 과정에서 사용한 ' OR 1=1 --은 SQL Injection에서 자주 사용되는 형태이다. OR 1=1은 항상 참이 되는 조건이고 --는 뒤의 내용을 주석으로 처리할 때 사용된다. 다만 이 문제에서 실제로 Flag를 얻는 데 결정적인 역할을 한 것은 SQL Injection보다는 admin 쿠키의 값을 직접 변경한 것이었다.

### 익스플로잇


먼저 로그인 페이지에서 Joe로 로그인하는 것은 비밀번호 때문에 실패하였다. 그래서 Joe가 아닌 다른 사용자 이름을 입력하고 임의의 비밀번호를 입력하여 로그인을 시도하였다. 비밀번호를 정확하게 알지 못했는데도 로그인에 성공하였다. 이후 /flag 페이지에 접속했지만 No flag for you가 출력되었다. 따라서 개발자 도구를 열어 웹사이트의 쿠키를 확인하였다. Application, Cookies에서 admin이라는 쿠키의 값이 False로 되어 있는 것을 발견하였다. 이 값은 현재 사용자가 관리자가 아니라는 의미로 보였기 때문에 False를 더블클릭하여 True로 수정하였다. 수정한 후 /flag 페이지를 새로고침하자 이전의 No flag for you 대신 Flag가 출력되었다. 즉, 서버가 클라이언트가 가지고 있는 admin 쿠키를 신뢰하고 있었기 때문에 쿠키의 값을 변경하는 것만으로 관리자 권한을 얻을 수 있었다.

## 배운 점

이번 문제를 통해 쿠키는 웹사이트가 사용자의 브라우저에 저장해 두는 작은 데이터이며, 로그인 상태나 사용자와 관련된 정보를 저장하는 데 사용될 수 있다는 것을 알게 되었다. 또한 개발자 도구의 Cookies 메뉴를 이용하면 현재 웹사이트가 사용하는 쿠키를 확인할 수 있다는 것도 배웠다. 특히 이번 문제에서는 admin=False라는 값을 True로 바꾸었을 뿐인데 관리자 권한을 얻을 수 있었다. 이를 통해 브라우저에 저장된 값을 무조건 믿으면 보안 문제가 발생할 수 있다는 것을 알게 되었다. 관리자 여부처럼 중요한 정보는 사용자가 직접 수정할 수 있는 쿠키에만 의존하면 안 되고, 서버에서 사용자의 권한을 다시 확인해야 한다는 것도 이해하게 되었다. 추가로 SQL Injection에서 OR 1=1과 --가 어떤 의미로 사용되는지도 간단하게 알아볼 수 있었다. 처음에는 단순히 비밀번호를 맞혀야 하는 문제라고 생각했지만, 실제로는 로그인 성공, /flag 접근, 쿠키 확인, 관리자 값 변조 순서로 웹사이트의 동작을 하나씩 확인하는 것이 중요하다는 것을 배웠다.
